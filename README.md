## 💡 배경

<br>

🚑 천안시는 충청남도 권역응급의료의 중심 역할을 수행하고 있으며,
인근 지역에서도 많은 응급환자가 유입되는 지역이다.

📈 그러나 응급의료기관의 분포와 실제 응급의료 수요는 지역별로 차이가 존재하며,
교통 혼잡과 거리 등의 영향으로 응급의료 접근성이 낮은 지역이 발생할 수 있다.

🚦 특히 시간대별 교통 상황에 따라 응급실 도착 시간이 크게 달라질 수 있어,
단순 거리보다 **실제 이동시간 기반의 접근성 분석**이 중요하다.

🎯 본 프로젝트는 공공데이터를 활용하여 지역별 응급의료 접근성을 분석하고,
응급의료 사각지대와 의료 자원 배치가 필요한 후보 지역을 도출하는 것을 목표로 한다.

## ✨ 핵심 기능

<br>

### 1️⃣ 응급의료 사각지대 분석

- 구급 활동 출동 패턴 분석
- 응급 발생 위험 분석
- 취약인구 비율 분석
- 대체 병원 부족도 분석
- 지역별 응급 취약도 시각화

<br>

### 2️⃣ AI 기반 응급실 이동시간 예측

- 시간대별 교통량 분석
- 실시간 교통 데이터 반영
- 기상 데이터 반영
- 응급실 예상 이동시간 예측

<br>

### 3️⃣ 응급의료 사각지대 및 의료 자원 배치 후보지역 도출

- 지역별 응급 취약도 산출
- 응급의료 접근성이 낮은 지역 도출
- 응급실 이동시간이 오래 걸리는 지역 분석
- 의료 자원 배치가 필요한 후보 지역 도출
- 지도 기반 분석 결과 시각화

## ⚙️ 구현 파이프라인

<br>

```text
1️⃣ 지역 분석
        ↓
2️⃣ 병원 DB 구축
        ↓
3️⃣ AI 기반 이동시간 예측
        ↓
4️⃣ 응급 취약도 산출
        ↓
5️⃣ 응급의료 사각지대 및 의료 자원 배치 후보지역 도출
```

<br>

| 단계 | 내용 |
|---|---|
| **1️⃣ 지역 분석** | 구급 활동 출동 패턴, 응급 발생 위험, 교통량 등의 데이터를 분석하여 지역별 응급의료 수요를 파악 |
| **2️⃣ 병원 DB 구축** | 천안시 및 인근 응급의료기관의 위치, 종류 등의 정보를 수집하여 병원 DB 구축 |
| **3️⃣ AI 기반 이동시간 예측** | 교통량, 도로 정보, 기상 데이터 등을 활용하여 응급실까지의 예상 이동시간 예측 |
| **4️⃣ 응급 취약도 산출** | 이동시간, 교통 혼잡도, 취약인구 비율, 응급 발생 위험 등을 종합하여 지역별 응급 취약도 계산 |
| **5️⃣ 분석 결과 도출** | 응급의료 사각지대와 의료 자원 배치가 필요한 후보 지역을 도출하고 지도 기반으로 시각화 |

<br>

### 🔍 응급 취약도 산출 지표

지역별 응급 취약도는 다양한 공공데이터를 종합하여 계산한다.

| 지표 | 설명 |
|---|---|
| 🚑 응급실 이동시간 | 병원까지의 예상 이동시간 |
| 🚦 교통 혼잡도 | 시간대별 도로 혼잡 수준 |
| 👨‍👩‍👧 취약인구 비율 | 고령층 등 의료 취약 인구 비율 |
| 📈 응급 발생 위험 | 과거 구급 활동 데이터를 기반으로 한 응급 발생 위험 |
| 🏥 대체 병원 부족도 | 주변 응급의료기관 접근 가능성 |

<br>

> **응급 취약도는 프로젝트 진행 과정에서 지표별 가중치를 조정하여 산출할 예정입니다.**

## 🚀 시작하기

<br>

### 프로젝트 다운로드

```bash
git clone https://github.com/{organization}/cheonan-data-challenge.git

cd cheonan-data-challenge
```

### Conda 환경 생성

```bash
conda create -n cheonan-ai python=3.13 -y

conda activate cheonan-ai
```

### 필요한 라이브러리 설치

```bash
pip install -r requirements.txt
```

<br>

### `.env` 예시

```text
TMAP_APP_KEY="발급받은 키 값"
TRAFFIC_API_KEY="발급받은 키 값"
WEATHER_API_KEY="발급받은 키 값"
```

> **※ 프로젝트에서 사용하는 API는 진행 과정에 따라 변경될 수 있습니다.**

## 🌿 Git 컨벤션

<br>

### 브랜치 전략

- `main`
  - 항상 실행 가능한 안정 버전 유지
  - 직접 Push 금지
- 개인 브랜치
  - 기능 개발 및 실험 진행
  - 작업 완료 후 Pull Request를 통해 병합

<br>

### 커밋 컨벤션

| 타입 | 설명 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 코드 구조 개선 (동작 변경 없음) |
| `docs` | README 및 문서 수정 |
| `test` | 테스트 코드 추가 및 수정 |
| `style` | 코드 포맷팅 (로직 변경 없음) |
| `chore` | 환경설정, 의존성 등 기타 작업 |

<br>

### ⚠️ 주의사항

- API Key 및 `.env` 파일은 절대 커밋하지 않습니다.
- 원본 데이터(raw)는 수정하지 않습니다.
- 대용량 데이터는 Git에 업로드하지 않습니다.
- 공공데이터 사용 시 라이선스를 확인합니다.
